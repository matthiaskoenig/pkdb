# Website screenshots

`render.mjs` renders the screenshots of [the web interface guide](../../docs/web-interface.md) into `docs/images/web/`, in the light theme, 1440 pixels wide, starting in a window 900 pixels high:

- as a visitor: `login.png`, `browse-studies.png` and `browse-measurements.png` (the data search on its Studies and Measurements tabs), `study-details.png` (the record page of a study without a study page) and `timecourse.png` (the plot of its timecourse), `studies.png` (the Studies page), `study-metadata.png` and `study-data.png` (a study page on Metadata and on Data);
- as the curator of that study: `studies-curator.png` (the Studies page), `study-curator-data.png` and `study-curator-review.png` (the study page on Data and on Review).

It drives the real website in Chromium by roles and labels, against the disposable website of the browser tests ([tools/frontend_testing](../frontend_testing/README.md)): its production build behind Nginx, with the artificial fixture data of `serve.py` in a database on a tmpfs. To that fixture the renderer adds `caffeine/Demo2020` and `caffeine/Draft2021`, the synthetic studies of [the curation app screenshots](../curation_docs/README.md) (`tools/curation_testing/fixture`), through the real upload path: it signs in as the fixture account `curator`, creates an API key that may upload studies, as **Account settings** does, and runs `pkdb upload` with it on a copy of the studies. The copy is released and public, so that a visitor sees it, and has an issue. Draft2021 gets the substance that its fixture misspells on purpose and the sex of its subjects, which a released study needs, so that it validates. The images show no real publication or account. The study pages show Demo2020, with its figure, its rows, its review items and its two warnings, and the record page shows the study format 1 study `FRONTEND_SCOPE` of the fixture.

Each image shows the page from its top to the end of its content, without the footer, whose release and commit change with every build. The images of the data search and of the record page, which are longer, end at 1200 pixels, above the first line of text that this height would cut. For a Data image the window gets the height at which the panes end 16 pixels below their longest content, and the separator between the source and the rows stands where the rows table shows only whole columns: the fade at the end of a table that scrolls sideways covers only the start of the next column. The renderer fails when a rows table cuts a column.

You need Docker, the frontend dependencies with Playwright Chromium, the built website, and [uv](https://docs.astral.sh/uv/). From the repository root:

```bash
(cd frontend && npm ci && npx playwright install chromium && npm run build)
tools/website_docs/run.sh
```

`run.sh` starts the Compose project `pkdb-frontend-test` of the browser tests from a fresh fixture, builds the backend from this checkout, runs `render.mjs` and removes the project again on exit, as `npm run test:e2e` does; it never touches another project or a deployment volume, and the fixture of the browser tests stays as it is. To render against that website while it already runs, run `node tools/website_docs/render.mjs`, which uploads the studies again; set `PKDB_WEBSITE_URL` for another address on a loopback interface. The renderer never prints the API key. Before each image it waits until the page shows the expected content, nothing loads, no menu is open and nothing moves, moves the pointer away and takes the focus from every control; `../curation_docs/capture.mjs` holds the waiting and the framing that both renderers share. It quantizes the images with [`optimize_png.py`](../curation_docs/README.md) of the curation app screenshots. Set `PKDB_WEBSITE_SCREENSHOTS` to a folder to write the images there instead. Look at every image before you commit it.
