# Release notes for pkdb 0.12.4

pkdb 0.12.4 makes the local curation app compact, so that a screen shows as much of a study as possible, and joins its Sources and Tables sections into one Data section, which shows a source of a study beside the rows of its tables. The local curation server answers a write that it refuses before it closes the connection. The database needs no migration.

## Changes

- The Data section of the local curation app replaces the Sources and Tables sections, which showed the same files twice (#920). A navigator lists the sources with a thumbnail of their image and the table files in the order of the workbook sheets, each with the number of its problems and open review items; the source pane shows the selected source, the image of a table with its raw extraction or a figure with its digitization, and the rows pane the rows of the selected table file. A click on a row selects it, and a click on a point of the digitization selects its row, which the plot rings. The source, the table file and the line are part of the URL of the section, and the links to the Sources and Tables sections open the Data section. Without a selection the section opens the first source with problems. The separator between the panes can be dragged or moved with the arrow keys, and the browser remembers where it was put.

- The local curation app is compact (#920). A study shows its identity, title, state and actions on one line with its sections as tabs below it, which leaves all but 109 pixels of a window of 1600 by 1000 pixels to the section; the rows of a table are 22 pixels high, the overview shows one line per study and fits a width of 1280 pixels, and the metadata form has two columns. Buttons, fields and switches are smaller, and every control stays at least 24 pixels high.

- The local curation app server reads and discards the body of a write that it refuses before reading it, such as a write without a session (401) or without the action token (403), before it closes the connection (#915). Closing with the body unread reset the connection, so on Windows the browser could lose the answer and see a network error instead; a client test failed at random on Windows this way and stopped the first release run of 0.12.3.
