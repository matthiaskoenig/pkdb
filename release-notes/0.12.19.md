# Release notes for pkdb 0.12.19

pkdb 0.12.19 is a security release: the `pkdb` package and the backend require Pillow 13.0.0, which fixes 41 advisories of the earlier releases, five of them critical, and the former upper bound `<13` no longer keeps projects which depend on `pkdb` from taking the fix. The database needs no migration.

## Changes

- Security: the `pkdb` package and the backend require Pillow 13.0.0 or newer and lock it (#1054); Pillow 13.0.0 fixes 41 advisories of the earlier releases, among them the critical GHSA-v9pv-5gc8-w2m6, GHSA-5x8w-8jj5-q52h, GHSA-332p-7hrc-92wf, GHSA-w889-685w-c8fh and GHSA-8g5g-8vmr-9782. The former upper bound `<13` blocked projects which depend on `pkdb` from taking the fix.
- Security: the backend locks authlib 1.9.1 (GHSA-8m4g-j4wp-wgcg, GHSA-c73q-w75p-j82v, #1047), joserfc 1.7.6 (GHSA-9pg5-8c7x-5hfx, #1048), dnspython 2.9.0 (GHSA-45c3-73f7-pv4m, #1049), fastmcp 4.1.5 (GHSA-7xgj-8392-5q4r, GHSA-vqqp-x5qm-5qp4, #1053, #1055) and opentelemetry-api 1.45.2 (CVE-2026-114603, #1055); the frontend locks follow-redirects 1.16.2 (GHSA-mrwp-f3q8-3g9p, #1050) and runs its tests with vitest 5.0.5, whose `@vitest/mocker` fixes GHSA-qxg6-89mg-rqv8 and GHSA-xp26-3454-mjgp (#1055).
- Dependencies: the backend updates 14 packages, among them fastapi 0.162.0, sqlalchemy 2.1.6, pydantic-settings 2.16.2 and certifi 2026.10.23, and beartype 0.23.1 on Python 3.15 (#1053); the locks of the `pkdb` package and of the backend move to the newest releases within their bounds, among them pkpdutils 1.4.0 and pydantic 2.14.2 on Python 3.15 as on 3.14 (#1055). The documentation builds with zensical 0.0.73 or newer (#1051), the workflows install uv with setup-uv 10.3.3 (#1052).
- The client is type checked with ty 0.0.95 (#1055): `pkdb curate` passes the creation flags of an open command to `Popen` explicitly.
