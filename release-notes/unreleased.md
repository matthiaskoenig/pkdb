# Unreleased

- The paper viewer of the local curation app no longer logs two errors of PDF.js to the console of the browser when a PDF closes while a page of it loads, as when another PDF is chosen quickly (#930).
- Continuous integration runs its test jobs in parallel and skips them for a pull request that changes only the documentation: the frontend browser tests run one job per browser and the curation app browser tests on every core, the jobs that start the backend image build it from a layer cache, every backend test copies a template database that is migrated once instead of migrating its own, the test database runs without durable writes, and the five speed tests of the client run apart with `pytest -m slow` (#950).
- The open actions of the local curation app and `pkdb tables open` no longer fail after 15 seconds while the program they started, such as LibreOffice, runs (#943). The app starts the open command without waiting for the program that it starts: a command that fails within 2 seconds shows its error as before, and a later failure goes to the log file and the terminal of `pkdb curate`.
- The overview of the local curation app keeps up with typing in **Search studies** in a workspace of 1,000 studies: it filters 150 ms after the last keystroke and renders only the rows in view, the local server answers an unchanged state without building it, and typing in the Metadata form redraws only the changed field. The Substance and Curator lists sort numerically and ignore case, and the rows of `/local/state` no longer carry `problems`, which the study detail does (#953).
- The local curation app shows the state of `study.json` in a banner under the section tabs of Metadata and Data, which replaces the save bar at the bottom: it says that there are no unsaved changes, turns amber and names the changed fields when there are, and keeps its height, so that the form does not move; it stays in view while the page scrolls as long as it has something to say, and the other sections show it from their opening while there are unsaved changes, a notice or a problem of the last save, until the curator leaves them. Ctrl+S (Cmd+S on macOS) saves them from anywhere on the study page, also a collaborator that is typed but not yet added. The header of a study wraps onto more lines instead of cutting the text of its chips, and shows what the study is doing, such as Validating for a moment after a save, beside its title, so that the header keeps its height, and in a narrow window the source pane of the Data section fits a short image instead of leaving empty space below it (#952).
- Tables number their lines as curators count them. In a table with a header, such as `outputs_Fig6.tsv`, the header is line 0 and the first entry line 1 in the curation app (the rows, the problems and the address of the Data section), in validation messages, in conflicts of `pkdb tables sync` and on the command line, and `pkdb review acknowledge --line` takes these lines; a raw table still starts at line 1. A location names the line and the address of the cell in the workbook, such as `line 96 · error_bar · workbook cell Y97` in the app and `outputs_Fig6.tsv → line 96 → error_bar → workbook cell Y97` in `pkdb validate`, and problems of the workbook itself keep the rows of its sheets. Reports of earlier validations show the old numbers until the study is validated again, which `pkdb curate` does when it starts (#949).
