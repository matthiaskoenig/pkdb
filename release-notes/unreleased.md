# Unreleased

- `pkdb curate` answers the curation app at once while it queues the initial validations of a large workspace. It saved its state after each queued job, so the app and every action waited for seconds after a start on 1,000 studies, about 3 seconds on a fast machine and 11 seconds in continuous integration; it now saves once after queueing them, and so does **Validate** for many selected studies (#976).
- `pkdb migrate` no longer drops numbers that `study.json` does not map. The converter drops a characteristic, output or timecourse point without any value (`valueless_row`), but in many format 1 studies a row is valueless only because the template of its table does not map the columns that hold its numbers, such as the `median`, `min` and `max` of a tmax row whose template maps `mean` and `sd`, a `cv` column, or a `value` column where the template maps `mean`; the first cutover and a later run lost such numbers in more than 80 studies, such as the `value` column of liraglutide/Elbrond2002 Fig2b (272 points) and `min` and `max` of apixaban/Bashir2018 Tab2. The equivalence gate now reads the format 1 row of each dropped row and refuses the study as `mismatch` with the issue code `unmapped_value` when a statistic column (`value`, `mean`, `median`, `min`, `max`, `sd`, `se`, `cv`, `gmean`, `gsd`, `gcv` or `mean_pm`, in any case) holds a number that no template of the row maps. Each difference names the table, the format 1 file, sheet and row and the columns with their numbers, and says to map them in `study.json`. The study is not written; rows without any number stay intended `valueless_row` drops. The format 1 parser now locates each characteristic of a group that spans several rows of a sheet at its own row instead of the first row of the group, which also corrects the rows of dropped characteristica in `migration.json` and `migration.md`, and the mismatch section of `migration.md` names its codes "Issue codes", as they are no longer only those of format 2.
