# Release notes for pkdb 0.10.0

- tooling: uv, ruff, ty, tox and pre-commit for the backend, matching pkdb_data
- backend tests (pytest-django) run against postgres and elasticsearch services, kept
  separate from the development stack (`docker-compose-test.yml`)
- GitHub workflows (`ci-cd`, `ruff`, `ty`, `documentation`) and repository policies
  (branch protection rulesets, `CODEOWNERS`, `dependabot.yml`)
- documentation site built with Zensical, published at
  [https://matthiaskoenig.github.io/pkdb](https://matthiaskoenig.github.io/pkdb)
- write requests of the REST API require an authenticated user
- the index update of a study (`api/v1/update_index/`) requires an authenticated user
  with write permission for the study, and answers other HTTP methods with 405
- read-only endpoints answer unsafe methods of anonymous clients with 403
- `IdCollection.expire` is evaluated per row
- `np.NaN`, removed by NumPy 2, replaced with `np.nan` (thanks to Mark Ramsey, #756)
- new optional setting `PKDB_ELASTICSEARCH_HOST` (defaults to `elasticsearch:9200`)
- `setuptools` declared as a runtime dependency (`drf-yasg` imports `pkg_resources` at
  load time, which a seedless uv venv does not provide), and the lock file re-resolved
  so matplotlib is compatible with NumPy 2
- docstrings for the backend modules
- the empty `pkdb_app/pkdata.py` module removed
- the swagger documentation of the `filter` and `statistics` endpoints moved to their
  method docstrings
